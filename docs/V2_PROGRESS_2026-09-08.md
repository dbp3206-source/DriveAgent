## Implemented and checked

- Active runtime: deterministic gathering + real ADK runner, no tools inside the
  generation round, max one model call, no automatic fallback. Canonical SQLite
  chat history is bounded and filtered by user/session.
- Persistent local quota reservations; SDK retries disabled, Google Developer API
  endpoint fixed (not Vertex). User confirmed free tier without billing. This app
  cannot observe quota consumed by other applications on the same Google project.
- Embedding batching (up to 32 chunks/request), quota reservation, count/dimension/
  finite-value validation before index replacement. Unchanged-index skip preserved.
- MCP 2.2.0 and A2A SDK 1.1.2 read-only protocol endpoints use the governed registry.
  Bearer tokens are user-bound, expire after one hour; no external write execution.
- Docs typed create/targeted-patch executor, UTF-16 indexing, named paragraph styles,
  read-back text verification, exact target/revision checking. Tables/images are
  rejected for targeted editing rather than silently flattened and overwritten.
- Durable operation ledger: user + request-key uniqueness, digest-bound approval,
  30-minute preview lifetime, atomic one-attempt claim, resource-ID checkpoint,
  uncertain state after a failure. A crash in running state is not automatically
  retried. This is not an exactly-once guarantee across the Google network.
- Authenticated Docs prepare/approve/status API, registry permission/scope checks,
  no model/protocol-triggered approval, no write retries, existing audit integration.
- Opt-in OAuth upgrade `/api/auth/google?capability=workspace` requests `drive.file`,
  not full Drive write. Default login remains read-only. Upgrade must return to the
  same active account. Granted scopes take precedence over requested scopes.

## Current API workflow (not yet a finished nontechnical UI)

1. Sign in normally. Optional Workspace consent adds `drive.file` only after the
   user chooses the connection. Enable Google Docs API in the existing project;
   do not enable billing. Application `drive:write` permission is also required
   (currently owner/super_admin; editor is deliberately not elevated silently).
2. POST `/api/documents/prepare` with a unique `request_key`, `action: create`,
   and `document: {title, blocks: [{text, style}]}`. Edit uses `patch` with
   document_id, tab_id, revision_id, exact old_text and new_text instead.
3. Review the returned exact spec/digest. POST `/api/documents/approve` with
   operation_id and approved_digest only after explicit approval. Both POST routes
   require an allowed Origin and authenticated session.
4. GET `/api/documents/operations/{id}` to inspect status/resource/result. If
   running/uncertain, inspect the created resource before making a new request.
   Never blindly resend with a different idempotency key.

`drive.file` covers app-created/explicitly selected files, not arbitrary pre-existing
Drive documents. A Google Picker or separately consented document scope remains
necessary for editing arbitrary existing files. Do not imply current support for that.
